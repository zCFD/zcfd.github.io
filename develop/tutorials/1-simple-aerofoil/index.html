Simple aerofoil

What is in this tutorial?

This tutorial runs your first zCFD simulation: air flowing past an aerofoil, the cross-section of a wing. The aerofoil is the NACA 0012, a symmetrical shape that has been measured in wind tunnels and simulated so often that it is the standard first test for a flow solver, so there are good results to compare with.

You download a ready-made mesh and control file. The mesh divides the space around the aerofoil into small cells, and zCFD works out the flow in every cell; the control file tells zCFD what to simulate. You then run zCFD, watch the run settle to an answer, and look at the results in Python and ParaView. The run takes under two minutes on an NVIDIA RTX 3060.

What you need?

To run the tutorial you will need an installation of zCFD and a valid licence (the free licence is sufficient for this tutorial). For instructions on installing zCFD please see installation and licensing.

The tutorial assumes that you are running all commands using a bash shell on Linux.

Step 1. Download the files

The tutorial bundle can be downloaded here. It contains a mesh file (naca0012.h5) and a zCFD control file (naca0012.py).

This tutorial assumes you unpack the bundle in your home directory, which creates a directory called tutorial_1_aerofoil.

cd ~
wget https://zcfd.zenotech.com/v2026.08.14860/tutorial_1_aerofoil.tgz
tar xzf tutorial_1_aerofoil.tgz
cd tutorial_1_aerofoil

Step 2. Walk through the input

The control file, naca0012.py, is a short Python script. All it does is build one Python dictionary, called parameters, that tells zCFD everything about the run: the physics, the numerical method, what to write out, and the mesh with its boundaries. This step walks through that dictionary from top to bottom. Each heading below is the name of a key, written exactly as it appears in the file, and the headings nest the same way the dictionary does: numerical scheme, for example, sits inside solver. Under each heading you'll find what that part controls, what each setting means, and why it has the value it has here. Each section ends with a link to that part's reference page, which lists every setting it accepts and its default; you don't need it to follow the tutorial. On a wide screen the whole control file sits on the right, with the part being described highlighted as you scroll.

config version comes first: it is always 2, and tells zCFD which form of control file to expect.

solver

solver holds every setting shared by the whole simulation: the physics, the numerics, how the run marches to convergence, and what it writes.

solver settings

solver settings chooses which solver runs the simulation.

  • type: "compressible" selects the density-based solver, which suits air at any speed. The alternative, "incompressible", suits liquids and very slow flows.

See solver settings.

equations

equations sets which equations are solved, and so what physics the simulation includes.

  • type: "rans" solves the Reynolds-averaged Navier–Stokes (RANS) equations. The Navier–Stokes equations describe how a viscous fluid moves. Most real flows near a surface are turbulent: full of small, fast, chaotic eddies, far too fine to capture on a mesh like this one. RANS solves for the average flow instead, and adds a turbulence model to represent the effect of the eddies on it. How turbulent a flow is depends on its Reynolds number, which compares the fluid's momentum with its viscosity. Here it is 6 million, and at that value the thin layer of air next to the aerofoil, the boundary layer, is turbulent, so RANS is the natural choice.
  • turbulence: picks the turbulence model. "model": "sst" is Menter's SST model, a robust general-purpose choice for flow that stays attached to an aerofoil.
  • precondition: True switches on low-Mach-number preconditioning. The Mach number is the flow speed divided by the speed of sound; here it is 0.15. At such low Mach numbers sound waves travel far faster than the flow, which makes the equations zCFD solves slow to converge and less accurate. Preconditioning rescales them to remove the problem, and is recommended below about Mach 0.3.

See equations and Choosing a turbulence model.

fluid properties

fluid properties describes the fluid: here, air treated as an ideal gas.

  • material: "air" names the fluid.
  • gamma: 1.4, the ratio of specific heats of air.
  • gas constant: 287.0 J/kg/K, the specific gas constant of air.
  • sutherlands const: 110.4 K, the constant in Sutherland's law, which sets how the viscosity varies with temperature.
  • prandtl no: 0.72, the laminar Prandtl number, which relates heat conduction to viscosity.
  • turbulent prandtl no: 0.9, the same ratio for the turbulent transport the SST model adds.

These are the standard values for air. See fluid properties.

reference conditions

reference conditions defines named flow states. Boundary conditions, the initial flow and the force coefficients all refer to these states by name.

IC_1

IC_1 is the freestream: the undisturbed flow far from the aerofoil.

  • temperature: 300 K.
  • pressure: 101325 Pa, standard atmospheric pressure.
  • v: the freestream velocity. vector gives its direction, along the mesh's x axis, and mach its size, Mach 0.15: about 52 m/s at this temperature.
  • viscosity: 1.02145×10−5 kg m−1 s−11.02145 \times 10^{-5}\ \mathrm{kg\ m^{-1}\ s^{-1}}1.02145×10−5 kg m−1 s−1. With the aerofoil's 1 m chord, this gives a Reynolds number of 6 million, matching the experiments this case is usually compared with.
  • turbulence intensity: 0.052, the size of the velocity fluctuations in the incoming flow as a fraction of its speed.
  • eddy viscosity ratio: 1.0, the turbulent viscosity of the incoming flow relative to its laminar viscosity.

The last two set the turbulence entering the domain; these values suit a flow with little freestream turbulence. See reference conditions and Choosing initialisation and reference state.

initialisation

initialisation sets the flow the run starts from.

  • initial conditions: "IC_1" fills the whole domain with the freestream at the first cycle. The same state is also the reference for the reported force coefficients.
  • restart: False starts from that initial flow. True would continue from the solution an earlier run saved, as Steady-state RANS shows.

See initialisation.

numerical scheme

numerical scheme sets how the equations are discretised in space: how the flow in each cell is turned into the flux between neighbouring cells.

  • order: "euler_second" treats the flow variables to second order and the turbulence variables to first order. First order assumes the flow is constant inside each cell; second order lets it vary linearly across the cell, which is more accurate on the same mesh. A limiter, van Albada by default, stops the second-order values overshooting near sharp changes.
  • inviscid flux scheme: "roe" uses Roe's scheme, a standard method for working out how much mass, momentum and energy flows between neighbouring cells.

See numerical scheme and Choosing a spatial scheme.

time settings

time settings says what kind of run this is in physical time.

  • type: "steady" asks for a steady solution: one that does not change with time. Real flows are rarely truly steady, but an attached flow round a streamlined aerofoil is close enough, and a steady run is far cheaper than a time-accurate one.

See time settings and Choosing a time-marching scheme.

convergence control

convergence control sets how the solver reaches that steady solution. It starts from the initial flow and improves it a little on each pass, called a cycle. When further cycles stop changing the results you care about, the run has converged.

scheme
  • name: "implicit euler" takes each step by solving a linear system, which allows large steps and so few cycles.
cfl

The CFL number sets how big a step each cycle takes, relative to the size of each cell and the speed of the flow through it. Too large and the run becomes unstable and fails; too small and it needs many more cycles.

  • cfl: 50, the CFL number the run works at.
  • cfl ramp: how the CFL number climbs to 50. The single ramp here is "exponential": it starts at the initial value of 1 and multiplies the CFL number by the factor 1.1 each cycle, reaching 50 after about 40 cycles. The first cycles, far from the answer, therefore take small steps.

See CFL control.

cycles
  • cycles: 1500, the number of cycles the run takes before it stops. This case has settled well before then.

See convergence control.

output settings

output settings sets what zCFD writes during and after the run. It has two parts: the report, a small table written as the run goes, and the solution, the full flow field written to files for viewing.

report

report writes one row of residuals and forces to naca0012_report.csv at a set interval, and prints the same values in the log. A residual measures how far the current solution is from satisfying one of the equations; the residuals fall as the run converges. zMon plots this file.

  • frequency: 10, so a row every 10 cycles.

  • forces: the force blocks. Each one sums the forces on a set of boundary zones and adds them to the report. The single block here, FR_1:

    • name: "wall", which prefixes the columns it adds: wall_Fx, wall_Fy and wall_Fz for the total force, wall_Fpx… for its pressure part and wall_Ffx… for its friction part, and wall_Mx… for the moments about the origin.
    • zones: [4], the aerofoil surface.

    Forces are reported as coefficients, divided by the dynamic pressure of IC_1 and a reference area that defaults to 1. With the mesh's 1 m chord and unit span, wall_Fx is the drag coefficient here.

See report.

solution

solution lists the variables written to the flow-field files, for viewing in ParaView.

  • surface variables: written on the boundaries, one file per boundary type: naca0012_wall.vtkhdf, naca0012_farfield.vtkhdf and naca0012_symmetry.vtkhdf. Here the velocity V, pressure p, Mach number, pressure and skin-friction coefficients cp and cf, and the pressure and friction forces on each face.
  • volume variables: written in every cell, to naca0012.vtkhdf. Here the velocity, pressure, temperature T, density rho, Mach number, cp, and the eddy viscosity eddy.

The control file sets no frequency for the solution, so the files are written once, at the end of the run, along with the checkpoint naca0012_results.h5 used for restarts. The report frequency and the solution frequency are separate: the report is cheap and written often, the flow-field files are large and usually written rarely. See solution and Output variables.

model

model holds one entry per mesh. Each entry is a model: a mesh with its own boundary conditions.

naca0012

The key, naca0012, names the model. It also names the model's output folder and files: naca0012_OUTPUT/naca0012/, with naca0012_report.csv, naca0012.vtkhdf and the rest inside. The folder above, naca0012_OUTPUT, takes its name from the control file.

mesh
  • mesh: "naca0012.h5", the mesh file, in zCFD's own HDF5 format, read from the directory zCFD runs in. Meshes from other tools are converted to this format first; see Preparing a mesh.
boundary conditions

boundary conditions assigns a condition to each group of boundary faces. The groups are the mesh's zones, numbered when the mesh was made; each condition lists its zones by number in zones. A mesh converted with zCFD's tools comes with a zone helper file that maps the zone names from the meshing tool to these numbers; see Zone identifiers. This mesh has four zones: the outer boundary, the two side faces, and the aerofoil.

The keys BC_1, BC_2 and BC_3 are names; any name will do.

BC_1

The outer boundary of the domain.

  • zones: [1].
  • type: "farfield", a boundary far enough from the aerofoil to see the undisturbed flow.
  • condition: "IC_1", the flow state it imposes.
  • kind: "riemann" lets flow pass both in and out without reflecting waves back into the domain.
BC_2

The aerofoil surface.

  • zones: [4].
  • type: "wall".
  • kind: "no slip": the flow velocity is zero at the surface, as for any viscous flow. Note the space in the name.
BC_3

The two side faces of the mesh, normal to y.

  • zones: [2, 3].
  • type: "symmetry": no flow passes through these faces, and the flow on each side mirrors the other. This makes the aerofoil behave as if it had an infinite span, so the mesh needs only one cell across it.

See Choosing boundary conditions.

Step 3. Run

  1. Activate your zCFD environment, which puts zCFD's commands, and the Python it uses, on your path:
source <ZCFD_INSTALL_PATH>/bin/activate
  1. Check the control file for errors with validate_input:
cd ~/tutorial_1_aerofoil/
validate_input naca0012.py
  1. Run zCFD in the case directory:
run_zcfd -c naca0012.py

zCFD will attempt to detect the number of CPU cores and any GPUs present and make use of them. If you want to manually configure this see invocation and flags.

Step 4. Monitor

zMon shows the residuals and forces of a run as it goes, and of a finished run. Open it on the control file:

source <ZCFD_INSTALL_PATH>/bin/activate
cd ~/tutorial_1_aerofoil/
zmon naca0012.py

A browser opens on the zMon dashboard; Monitoring a run describes each panel. The plots below are the residual and force panels as zMon draws them; Step 5 shows how to plot the same data yourself.

Residuals

The residual of each equation measures how far the current solution is from satisfying it: the lower the residual, the more converged the solution. There is one for each equation: density rho, momentum in each direction, energy rhoE, and the two turbulence variables rhok and rhoOmega. The report, the log and the script write the momentum residuals rhoV[0], rhoV[1] and rhoV[2], for x, y and z; zMon names them rhoU, rhoV and rhoW.

The residuals fall fastest in the first few hundred cycles, as the flow develops from the uniform initial state. The density residual falls about four orders of magnitude before levelling off. rhoV[1], the momentum across the span, stays near round-off throughout, because the flow has no velocity across the span. The turbulence residuals behave differently: rhok rises as the boundary layer forms, and rhoOmega falls from a large initial value. By 1200 cycles every residual is flat, which, with the forces below, shows the solution has converged.

Forces

The force panels show the x and z forces on the wall. The aerofoil is symmetrical and meets the flow at zero angle of attack, so the x force is the drag and the z force the lift. The lift should be zero and the drag positive.

The drag falls quickly from its initial value and settles after a few damped oscillations; the lift oscillates about zero at around 10−510^{-5}10−5 before dying away. Both traces are flat from 1200 cycles onwards. The drag coefficient settles at 0.0082, against 0.00828 from NASA's CFL3D code on a finer grid of the same family (897 × 257 points).

Step 5. Post-process

First activate your zCFD environment, which provides Python with zutil, h5py and ParaView:

source <ZCFD_INSTALL_PATH>/bin/activate

Python

This script draws the residual and force plots shown in Step 4. get_zcfd_result finds the run's output from the control file, and report.data is the report as a table, one column per quantity. Save the script as plot_convergence.py in the case directory:

import matplotlib.pyplot as plt

from zutil.fileutils import get_zcfd_result

report = get_zcfd_result("naca0012.py").report.data

fig, ax = plt.subplots()
for column in ["rho", "rhoV[0]", "rhoV[1]", "rhoV[2]", "rhoE", "rhok", "rhoOmega"]:
    ax.semilogy(report["Cycle"], report[column], label=column)
ax.set_xlabel("Cycle")
ax.set_ylabel("Residual")
ax.legend()
fig.savefig("residuals.png", dpi=200)

fig, (drag, lift) = plt.subplots(1, 2, figsize=(10, 4))
drag.plot(report["Cycle"], report["wall_Fx"])
drag.set_title("Drag coefficient (wall_Fx)")
lift.plot(report["Cycle"], report["wall_Fz"])
lift.set_title("Lift coefficient (wall_Fz)")
for ax in (drag, lift):
    ax.set_xlabel("Cycle")
fig.savefig("forces.png", dpi=200)

Run it:

python plot_convergence.py

It writes residuals.png and forces.png. Batch post-processing with Python scripts lists what get_zcfd_result provides.
