.. _output_variables:

Output variables
----------------

Which variable names are valid for ``surface_variables``, ``volume_variables`` (:ref:`write output <write_output>`) and ``report.monitor.*.variables`` (:ref:`reporting <reporting>`) depends on the equation type being solved, and — for RANS — on the turbulence model. The schema (``zutil/zutil/validate/schemas/output_variables.py``) builds each equation type's valid set incrementally: every equation type gets the base set below, then adds the variables for its physics tier. A request for a variable outside the valid set for the current equation type fails validation.

The equation types are: ``euler``, ``viscous``, ``rans``, ``les``, ``incomp viscous``, ``incomp rans``, ``incomp les``. Each tier below is cumulative — ``rans`` and ``les`` get everything listed under Base, Euler-tier, Viscous-tier, LES-tier and RANS-tier.

Per-equation dynamic variables
================================

``var_i``, ``resvar_i``, ``resshare_i`` and ``vargrad_i`` (solution value, residual, share of the total squared residual, and gradient of solved equation ``i``) are generated for ``i`` from 1 up to the number of solved equations, which depends on the equation type and, for RANS, the turbulence model:

.. list-table::
   :widths: 40 30 30
   :header-rows: 1

   * - Equation type
     - Turbulence model
     - Number of equations
   * - euler / viscous / les / incomp viscous / incomp les
     - --
     - 5
   * - rans / incomp rans
     - (default, e.g. sst)
     - 7
   * - rans / incomp rans
     - sa-neg
     - 6
   * - rans / incomp rans
     - sst-transition
     - 9

For example, an ``incomp rans`` case using the default (7-equation) turbulence model has ``var_1`` through ``var_7``, ``resvar_1`` through ``resvar_7``, and ``vargrad_1`` through ``vargrad_7`` available (used for the extra turbulence equations, e.g. ``var_6``/``var_7`` for the two SST transport variables in the :ref:`naca0012 <write_output>`-style examples elsewhere in this guide).

``resvar_i`` is divided by the cell volume only when :ref:`'scale_residuals_by_volume' <reporting>`
is set, so it always matches the reported residual norms.

``resshare_i`` is that cell's share of the total squared residual for equation ``i``, and the
values sum to one over the mesh. Threshold it at ``1/Neff_<eq>`` - reported when
:ref:`'residual_statistics' <residual_statistics_columns>` is on - to isolate the cells carrying
the residual, or sort the cumulative sum to answer "which cells hold the top 90%". It is exactly
``resvar_i`` squared and normalised, so the two always agree on which cells are the hot ones.

   * - Variable Name

.. note::
    A handful of variable names are not present in ``output_variables.py`` under any spelling and are unaccounted for in ``developer_docs/input-deck.md``'s "What's left":

    - ``lescfl`` and ``fdshield`` (DES/DDES/IDDES CFL and shielding-function outputs) — absent entirely.
    - ``cellorder`` (volume) and ``facecentre`` (surface) — absent entirely; ``centre`` remains valid in both contexts.
    - ``velocitygradient`` — only the shorter spelling ``velocitygrad`` is a valid variable name.
    - ``kinematicviscosity`` — only its alias ``nu`` is valid; the full name is not.
    - ``turbulenceintensity`` — only its alias ``ti`` is valid; the full name is not.
    - ``frictionvelocity`` — only its alias ``ut`` is valid; the full name is not.

    Separately, the schema defines a transition-model tier (``turbulenceintermittency``, ``transitionreynoldsnumber`` in ``output_variables.py``) that is never unioned into any equation type's valid set, so these two names are rejected for every equation type, regardless of turbulence model.

    ``les`` and ``rans`` resolve to the same valid-variable set (LES-tier variables are unioned in for both), so the tier split above does not gate anything differently between the two.
