# Aeroacoustics (FWH)

A [Ffowcs-Williams Hawkings (FWH) solver](../guide/working-with/aeroacoustics-fwh.md), which is used for
prediction of farfield noise, is included in the zCFD distribution. This tutorial uses the zCFD FWH
solver to calculate the sound experienced by two 'observer microphones' as a result of the aerodynamic noise
generated by the flow around the cylinder.

To predict noise at observer microphone locations, an FWH solver requires an initial unsteady CFD
solution. The example is based on the CFD simulation set up in [Time-accurate solution](./3-time-accurate-solution.md),
with some additional modifications to record the flow variables on an 'FWH surface' in the near-field, noise
generating region. The FWH solver then propagates the noise from the near-field FWH surface to the
observer microphones.

The FWH solver can be run in two ways - the
[run_fwh utility](../guide/working-with/aeroacoustics-fwh.md#using-the-zcfd-run_fwh-utility) and the
[fwh python module](../guide/working-with/aeroacoustics-fwh.md#using-the-zcfd-fwh-python-module). In this
tutorial, the simpler `run_fwh utility` is introduced first, followed by the `fwh python module` and
post-processing of the acoustic data.

::: {.track when="deck"}

## Step 1. Running zCFD with FWH output

The FWH solver is run on the shedding cylinder. Its inputs come from an _FWH surface_: data is collected on this
surface during a CFD simulation.

The files required for the fwh tutorial can be downloaded [here](https://zcfd.zenotech.com/tutorials/3/cylinder_fwh.zip).
In the zip file there's a FWH surface definition file, called _fwh_surface1.stl_. Since the
cylinder case has already been run in [Time-accurate solution](./3-time-accurate-solution.md), the FWH surface can be viewed in
ParaView alongside the cylinder CFD volume data (see [here](./3-time-accurate-solution.md#flow-field)), as below.
You may find the surface easier to see if you set the _view style_ to be _Feature Edges_ instead of _Surface_ for
the FWH surface, and increase the _Line Width_ in the _Geometry Representation_.

![fwh_surface1.stl plotted alongside CFD volume solution](/images/tutorial-4-cylinder-fwh-surface1.png)

The FWH surface encloses the noise generating near-field region, but does not intersect the wake, to
avoid spurious pseudo-sound [[1]](#citations), [[2]](#citations).

There's also a prepared control dictionary, _cylinder_fwh.py_. This is identical to tutorials 3's _cylinder.py_
apart from the output section, which is detailed below.

```python
"output settings": {
    "solution": {
        "format": "vtk",
        "surface variables": ["V", "p", "T", "rho", "cp"],
        "volume variables": ["V", "p", "T", "rho", "m", "cp"],
        "fwh interpolate": ["fwh_surface1.stl"],
        "frequency": {
            "fwh interpolate": 1,
            "volume data": 1000,
            "surface data": 1000,
        },
    },
},
```

This `solution` block — `{"output_settings": {"solution": {...}}}` — sits under the `solver` key of the control
dictionary, alongside `equations`, `convergence_control` and the other solver settings inherited from
_cylinder.py_. In this case, _fwh_interpolate_ data is output every timestep, using the
_fwh_surface1.stl_ FWH surface definition file. Volume and surface data is output much less often, since the run of
_cylinder.py_ above already provides it.

The `time_settings` block — `{"solver": {"time_settings": {...}}}` — is also changed to
run the simulation for 4 seconds, rather than 1.2. Run the CFD simulation in the normal way, using the command
below.

```bash
run_zcfd -m cylinder.h5 -c cylinder_fwh.py
```

Once the CFD simulation of the cylinder has run, the FWH interpolated data is in
`cylinder_fwh_OUTPUT/ACOUSTIC_DATA/fwh_surface1_FWHData.h5`. There is also a corresponding _xdmf_ file,
`cylinder_fwh_OUTPUT/ACOUSTIC_DATA/fwh_surface1_FWHData.xdmf`, which opens the FWH surface in
ParaView and see the pressure, velocity and density at each cell centre varying with simulation time. Use the
ParaView _Time_ controls to adjust the simulation time being viewed. You may find that changing the _view style_
to _Point Gaussian_ and increasing the _Gaussian Radius_ in the _Properties_ sidebar makes the cell values easier
to see.

## Step 2. Running the zCFD FWH solver

### Using the run_fwh utility

The `run_fwh` utility calculates the noise at an observer `Obs1`. `Obs1` is an observer that
is a fixed distance away from the cylinder: for a cylinder in a wind tunnel, `Obs1` would be a microphone
attached to the wind tunnel wall. Since `Obs1` is static relative to the FWH surface, it
is in the same [translational reference frame](../guide/working-with/aeroacoustics-fwh.md#reference-condition) as
the FWH surface, so the `run_fwh` utility can be used.

![FWH Observer and surface motions - CFD frame of reference](/images/tutorial-4-fwhdiagram-cyl1-obs1only.svg)

The `run_fwh` utility needs three inputs: a
[zCFD control file](../guide/working-with/aeroacoustics-fwh.md#zcfd-control-file), a
[reference condition](../guide/working-with/aeroacoustics-fwh.md#reference-condition) specification and an
[observers .csv file](../guide/working-with/aeroacoustics-fwh.md#observer-csv-file).

The zCFD control file is the control file for the zCFD simulation that created the FWH surface data,
in this case _cylinder_fwh.py_. _run_fwh_ reads _cylinder_fwh.py_ and finds a single FWH surface,
with data stored at `cylinder_fwh_OUTPUT/ACOUSTIC_DATA/fwh_surface1_FWHData.h5`.

Next, define a _reference condition_. In external flow simulations of this type, the _run_fwh_
_reference condition_ is the freestream conditions, defined as a zCFD reference condition block —
`{"solver": {"reference_conditions": {"IC_1": {...}}}}`. In this case, the freestream conditions are already
defined in _cylinder_fwh.py_ to define the farfield boundary condition, so _'IC_1'_ can be used for the
_run_fwh_ reference condition.

Lastly, define the name and location of each observer in a `.csv` file. The centre of the cylinder in
the CFD mesh is at (0.25,0,0), and `Obs1` is to stay (0,0,20) metres away from the cylinder centre
throughout the FWH simulation. The file `Observers.csv` (included in the tutorial [.zip file](#step-1-running-zcfd-with-fwh-output))
therefore contains the following:

```
Obs1, 0.25, 0.0,  20.0
```

With the inputs defined, run the _run_fwh_ utility by typing the following command within the
[zCFD command-line environment](/reference/command-line/invocation-and-flags).

```bash
run_fwh -c cylinder_fwh.py --reference_condition IC_1 --observer_locations Observers.csv
```

Running this command prints output to screen and to the `cylinder_fwh.fwh.log` file, and outputs the FWH
calculated pressure history at `Obs1` to `cylinder_fwh.fwh.Obs1.csv`. In the case where there are multiple noise
sources, the contribution of noise to each source is broken out, with the total observed noise also reported.
Suggested post-processing is introduced [below](#step-3-post-processing).

::: {.note}
The `run_fwh` command-line interface takes a zCFD control file, a reference-condition name and an observers
`.csv` file, whatever the control file's `config_version`. The FWH tools read the control dictionary's raw
parameters directly, rather than through the same schema-validated path as the solver: the `run_fwh` helper
module has not been updated for the current control-file format, and references a class that is not present in
`zutil.fileutils`. Check your local installation's release notes for the current status of these tools.
:::

### Using the fwh python module

As can be seen above, the _run_fwh_ utility is very easy to use and is applicable in most simple FWH
calculations. However, it has limitations - namely the fact that all observers and surfaces must be in the same
[translational reference frame](../guide/working-with/aeroacoustics-fwh.md#reference-condition), and that using
it when more than one FWH surface encloses a noise generating region will
[lead to double accounting](../guide/working-with/aeroacoustics-fwh.md#advanced-use).

Where the _run_fwh_ utility is not applicable, the
[fwh python module](../guide/working-with/aeroacoustics-fwh.md#using-the-zcfd-fwh-python-module) can be used
instead. This section uses the _fwh python module_ to calculate observer pressure histories at both
`Obs1` and `Obs2`, where `Obs2` is a 'flyby' observer whose pressure history cannot be calculated using the
_run_fwh_ utility.

![FWH surface and observer motions - CFD frame of reference](/images/tutorial-4-fwhdiagram-cyl1.svg)

#### FWH Observer and surface motions

The derivation of the FWH equations makes an important assumption: that of a 'quiescent medium' (still
air, with a free-stream velocity of zero). With a freestream velocity of _(0,66.8,0)_, the flow in this
CFD simulation does not satisfy this condition. To use the FWH solver, a
co-ordinate transformation is therefore required, as in the figure below. In the _run_fwh_ utility, this co-ordinate transformation is
performed automatically, whereas in the
[fwh python module](../guide/working-with/aeroacoustics-fwh.md#using-the-zcfd-fwh-python-module) the
surface and observer motions through the FWH quiescent medium are set up by hand.

In this 'quiescent medium' co-ordinate system, the cylinder and `Obs1` are 'flying' through the air. In this
co-ordinate system, `Obs2` represents a microphone fixed to the ground, as the cylinder
flies overhead.

![FWH surface and observer motions - FWH (quiescent medium) frame of reference](/images/tutorial-4-fwhdiagram-cyl2.svg)

#### Setting up the FWH solver inputs

With the motions of the observers and surface known, the FWH solver can be run. The python code required to
run the FWH solver is in the file _'run_fwh_solver.py_', and also written out below. It defines the surfaces,
observers and the solver settings, then use `fwh.solve()` to actually run the FWH solver.

```python
from fwh import fwh, motion
import json
import math

# FWH surface motion
c  = math.sqrt(1.4 * 277.7777 * 287)
v_surf = [0, - 0.2 * c, 0] # = [0,-66.8,0]
surfaceCentrePoint = motion.ConstantVelocityPoint([0.0, 0.0, 0.0], v_surf)
surfaceMotion = motion.NonrotatingSurface(surfaceCentrePoint)

# obs1 motion - [0,0,20] above cylinder centre
obs1_CFD_frame_posn = [0.25,0,20]
obs1Motion = motion.ConstantVelocityPoint(obs1_CFD_frame_posn, v_surf)

# obs2 motion - stationary, intersects with obs1 at t=2.5
obs2_posn = []
for i in range(3):
  obs2_posn.append( obs1_CFD_frame_posn[i] + 2.5* v_surf[i])
obs2Motion = motion.StationaryPoint(obs2_posn)

solverSettings = {
    "c": c,
    "dt": 0.002,
    "rho0": 101325.0 / (277.7777 * 287),
    "p0": 101325.0,
}

surfaces = {
    "surf1": {
        "motion": surfaceMotion,
        "fileName": "./cylinder_fwh_OUTPUT/ACOUSTIC_DATA/fwh_surface1_FWHData.h5",
    }
}
observers = {"Obs1": obs1Motion, "Obs2": obs2Motion}

pOut, tOut = fwh.solve(surfaces, observers, solverSettings)

dataForJson = {"p": pOut, "t": tOut}

with open("./FWH_data.json","w") as f:
    json.dump(dataForJson,f)
```

More details on FWH solver setup can be found [here](../guide/working-with/aeroacoustics-fwh.md#running-the-zcfd-fwh-solver),
but the most important concept is that _'motion classes'_ define observer and surface motions.
The available [point (observer) motions](../guide/working-with/aeroacoustics-fwh.md#point-observer-motion-classes)
are _'OriginPoint'_, _'StationaryPoint'_ and _'ConstantVelocityPoint'_. The available
[surface motions](../guide/working-with/aeroacoustics-fwh.md#surface-motion-classes) (which rely on a
[point motion](../guide/working-with/aeroacoustics-fwh.md#point-observer-motion-classes) to define the motion of
their centre) are _'NonrotatingSurface'_ and _'RotatingSurface'_.

The velocities and fluid properties used in the FWH simulation are taken from the _'cylinder.py'_ zCFD control
file. `solverSettings['dt']` has been set to be the same as the timestep between outputs in the FWH surface data
(0.002 seconds, see [above](./3-time-accurate-solution.md#output)).

In general, the motion of a point on an FWH surface is defined by
$\mathbf{x}(t)=\mathbf{x}_0+ \mathbf{V}_{surf}\ t$ in the FWH co-ordinate frame.
$\mathbf{V}_{surf}$ is defined by the user in the
[surface motion class](../guide/working-with/aeroacoustics-fwh.md#surface-motion-classes) (called
_surfaceMotion_ above) and $\mathbf{x}_0$ is the position defined by the FWH surface definition file
(_'fwh_surface1.stl'_, see [above](#step-1-running-zcfd-with-fwh-output)).

The centre of the cylinder in the CFD mesh is at (0.25,0,0), and `Obs1` is to stay (0,0,20) metres away
from the cylinder centre throughout the FWH simulation.
Since the cylinder 'travels with' the FWH surface (see the figure above), the motion of the point
(0,0,20) from the cylinder centre in the FWH co-ordinate frame is
$\mathbf{x}(t)=\left( (0.25,0,0) + (0,0,20) \right) + \mathbf{V}_{surf} t$.
The motion of `Obs1` is therefore set to $\mathbf{x}(t)= (0.25,0,20) + \mathbf{V}_{surf} t$.
`Obs2` is stationary in the FWH reference frame, and coincident with `Obs1` at _t=2.5_. The outputs are saved
to a json file called _FWH_data.json_.

### Running the FWH solver

The python code above is replicated in _'run_fwh_solver.py_'. To run the FWH solver, run the command
below from within the [zCFD command-line environment](/reference/command-line/invocation-and-flags).

```bash
python3 run_fwh_solver.py
```

This will output various information to the screen, including the 'valid min and max times' for each surface /
observer combination.

The valid min and max times denote the time window during which an observer receives data from all points on the
FWH surface.
A pressure signal emitted from a point on the FWH surface at time _t_ takes _r/c_ seconds to arrive at an
observer, where _r_ is the distance from the surface point to observer and _c_ is the speed of sound.
Therefore the valid observer time window will always be later than the FWH surface output time window (in this
case, 0.002:1.2 seconds) due to the distance from the FWH surface to the observer.
The valid observer time window will be narrower if the FWH surface is large, since the larger the surface the
larger the time delay between signals from different points on the surface reaching the observer becomes.

## Step 3. Post-processing

The notebook
`postprocess_fwh_module_data.ipynb` from the [.zip file](#step-1-running-zcfd-with-fwh-output) can be used to
post-process the FWH data. `postprocess_fwh_module_data.ipynb` uses the data from the
[fwh python module section](#using-the-fwh-python-module) of this tutorial, but an equivalent notebook which uses
the data from the [run_fwh utility section](#using-the-run_fwh-utility) is available in
`postprocess_run_fwh_data.ipynb`.

These notebooks contain a number of _zutil_ functions which may be useful for users wishing to perform acoustic
post-processing. The notebooks plot the pressure history _p(t)_ and power spectral density (PSD) at both
observers, as below.

`Obs1` moves through the FWH medium at a constant displacement from the cylinder centre (see the figure above).
The post-processing shows that the noise experienced by `Obs1` is dominated by a constant 10 Hz component,
which is the shedding frequency of the cylinder. Various harmonics of the 10 Hz signal are present in the power
spectral density plot for `Obs1`.

![Observer 1 p(t)](/images/tutorial-4-obs1-p.svg)

![Observer 1 PSD](/images/tutorial-4-obs1-psd.svg)

During the FWH simulation run in the [fwh python module section](#using-the-fwh-python-module) of this tutorial,
the cylinder gets closer to `Obs2` from 0 to 2.5 seconds, before getting further away from `Obs2` from 2.5 seconds
onwards. In the `Obs2` _p(t)_ plot the peaks are closer together from 0 to 2.5 seconds than they
are after 2.5 seconds. This is due to Doppler shift. The effect of Doppler shift also appears in the power
spectral density, which has a more rounded 10 Hz peak than that seen in `Obs1`.

![Observer 2 p(t)](/images/tutorial-4-obs2-p.svg)

![Observer 2 PSD](/images/tutorial-4-obs2-psd.svg)

`postprocess_fwh_module_data.ipynb` also creates _.wav_ files, which allow you to listen to the sound experienced
by `Obs1` and `Obs2`.

## Extensions

To become more comfortable with the FWH solver, various extensions to this exercise are possible. Here are some
suggestions.

1. Re-run the zCFD solver, but this time extract FWH data on the cylinder
   [wall](/reference/solver/output-settings#solution) instead of _fwh_surface1.stl_. Run the FWH solver (using
   the wall data as an [impermeable](../guide/working-with/aeroacoustics-fwh.md#how-does-an-fwh-solver-work) FWH
   surface) and compare the results to those achieved using the _fwh_surface1_ permeable FWH surface.
2. Re-run the zCFD solver, but this time also extract FWH data on the _fwh_surface2.stl_ and _fwh_surface3.stl_
   surfaces. These are like _fwh_surface1.stl_ but slightly larger. Run the FWH solver with these surfaces and
   investigate the effect of using different surfaces on the FWH results. You will have to do this using the fwh
   python module to avoid [double accounting](../guide/working-with/aeroacoustics-fwh.md#advanced-use).
3. Add extra observers of your choice to the FWH solver.
4. Use the file utility [writeFWHSurfaceFrequenciesFile](../guide/working-with/aeroacoustics-fwh.md#writefwhsurfacefrequenciesfile)
   to visually inspect the spatial distribution of different frequencies in the FWH surface.
5. Use the file utility [writeBlankedOffFwhSurfaceFile](../guide/working-with/aeroacoustics-fwh.md#writeblankedofffwhsurfacefile)
   to 'blank off' all FWH surface cells more than 5 cylinder diameters downstream of the cylinder's centre. Run
   the FWH solver using this modified surface, and based on this estimate how much of the shedding noise
   originates more than 5 diameters downstream of the cylinder.
6. Use the `solver.fwh_helper_functions` module to rewrite `run_fwh_solver.py` so that the `solverSettings`
   dictionary is automatically set based on the zCFD control file name and reference condition which were used
   in the `run_fwh` utility.

::: {.note}
Since the cylinder CFD simulation is '2.5D' (i.e. the mesh only has a single cell in the _x_ direction), the
distance scaling of _p(t)_ at observers will be non-physical.
:::

:::
